# Listing tiers and positioning

## Tiers, in order

| Tier | When | Examples of surface | Lead with |
|---|---|---|---|
| Integration marketplaces | When an integration ships | The app marketplaces of the tools you connect to (CRM, chat, ERP app stores), OS app stores | The workflow the integration enables, ROI |
| Agent and MCP registries | When you ship an MCP server or agent-facing product | The official MCP registry first (aggregators read from it), then other MCP directories, plugin directories | Agent and MCP angle |
| Launch communities | Launch week or a major release | Product launch sites, Show HN, builder communities | Outcome, honest maker story |
| AI directories | Weeks 1 to 3 after launch | AI tool directories with real organic traffic | AI-first architecture |
| SaaS and review sites | Rolling | Alternatives sites, B2B review sites | Alternative framing, ROI and use cases |
| Developer sites | When there is an API or SDK | Developer tool lists, open-source lists | Technical depth |

## Rules

- Destination first: the page a listing links to is live, indexed and converts.
- Different opening sentence and feature emphasis per tier; directories and AI engines discount duplicated copy.
- Verify the directory is live and legitimate before creating an account; skip sites with high authority but no organic traffic.
- Never ask for upvotes on launch sites; ask for feedback.
- Zero-review listings on review sites do little; plan reviews before submitting there.
- Submit once, check quarterly; do not edit listings weekly.
- Check the live link after approval and record what you saw.
- Keep descriptions, product counts and claims in step with the knowledge base, with dates.
