# Rights matrix, escalation triggers, DPA checklist

## Rights matrix (GDPR terms; map to your procedure)
| Right | Typical path | Notes |
|---|---|---|
| Access, portability | self-serve export if the product has one, else assisted | exclude secrets and other people's data |
| Rectification | self-serve profile edit | identity-sensitive fields may need re-verification |
| Erasure | self-serve deletion if available | statutory retention (billing) survives; log a tombstone |
| Restriction | usually assisted (freeze account, disable connectors) | deadline applies |
| Objection | marketing: always honoured; other grounds assessed | |
| Withdraw consent | self-serve toggles, cookie banner | |
| Automated decision | state whether any solely automated decision with legal effect exists | |
| Complaint | point to the competent supervisory authority | |

## Escalation triggers (stop, ask the owner)
- The request comes from a regulator, lawyer or court, or mentions a dispute or complaint.
- The person is a minor, or special category data is involved (health, beliefs, origin).
- Fulfilling it would reveal another person's data.
- The deadline is near or already passed.
- The request is for a customer's end users and the customer has not instructed you.
- Identity cannot be verified proportionately.

## DPA checklist (customer requests and mark-ups)
- Roles: customer controller, company processor, for customer data.
- Processing only on documented instructions.
- Confidentiality of personnel.
- Security measures (cite the security overview, not certifications you lack).
- Subprocessors: list, notice period, objection right.
- International transfers: mechanism (for example SCCs) and where data is hosted.
- Assistance with data subject requests.
- Breach notification timing.
- Deletion or return at the end.
- Audit: what evidence is offered (control matrix, questionnaire) and what is not.
