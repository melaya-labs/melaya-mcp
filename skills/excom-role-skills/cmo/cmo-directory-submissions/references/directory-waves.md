# Directory waves and operating rules

## Waves (work in this order)

1. Software review and entity sites: AlternativeTo, SaaSHub, G2 and Capterra vendor profiles, StackShare, GoodFirms and similar. AI assistants and knowledge graphs cross-check these for "best X" and "X alternatives".
2. MCP and agent registries (only if you ship an MCP server, plugin or agent skill): the official MCP registry and the directories that sync from it, Glama, Smithery, community MCP lists, IDE plugin marketplaces.
3. Launch sites and developer launchpads: Product Hunt, Hacker News Show HN, BetaList, DevHunt, Peerlist and similar. Plan these as launches, not form fills.
4. AI tool directories: the larger curated AI tool lists that accept free submissions.
5. Design galleries: only once the landing page is polished.

Check each target's current availability (free, paid, closed) on the day; directories change terms often.

## Operating rules

1. Zero unapproved spend: free tiers only. A target with no free path is logged as skipped, paid only, with a proposal.
2. Contact hygiene: the approved brand address and brand name only.
3. Human, factual copy from the approved fact sheet.
4. Check for an official API or agent endpoint before driving a browser form.
5. Never fill hidden inputs (hidden, zero-size, off-screen, or named like a spam trap).
6. Open embedded third-party forms in their own top-level page so uploads work.
7. Have logos, social image and screenshots ready before a batch.
8. Close verification loops the same day so listings do not stall unverified.
9. Curated lists on code hosts: read the contributing guide, the PR template and recent merged PRs first; respect lists that refuse vendor or AI-submitted entries; match ordering and punctuation; strip tracking parameters.
10. Check the log before every target and record a receipt after each attempt, so nothing is submitted twice.

## Log fields

directory, wave, product, free or paid, status (submitted, live, failed, skipped paid only), listing URL, date, note.
