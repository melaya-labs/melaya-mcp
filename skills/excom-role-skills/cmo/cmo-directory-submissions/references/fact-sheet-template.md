# Listing fact sheet template

Fill once per product from the knowledge base and the live site, then get it approved. Every directory asks for a subset of these fields in slightly different lengths.

## Product

- Name, product URL, pricing URL, privacy and terms URLs.
- Public contact: the shared brand address the owner approved. Never a personal email, phone number or home address, because directories get scraped by hundreds of aggregators.

## Copy

- Tagline, 40 characters: plain value in a few words.
- Tagline, 60 characters: names what the product does for whom.
- Description, 100 characters: the strict limit some MCP registries enforce.
- Description, 160 characters: who it is for, what it takes in, what it produces.
- Description, 500 characters: two factual paragraphs on the workflow, integrations and real differentiators.
- Curated-list bullet: "[Name] - one factual line, no hype".
- Four key features, each a concrete input to output capability.

## Taxonomy

- Primary category and 5 tags.
- Competitors it replaces (from the competitors note).
- Pricing model and starting price exactly as the public pricing page shows, with the date read.
- Free tier or trial details as shown publicly.

## Assets

- Square logo 512 px, small logo 48 px, social image 1200 x 630, three screenshots 1280 x 800 under 300 KB each.
- Use only assets from the team's brand kit.

## For MCP servers and agent tools

- The endpoint or install instructions as published in your public docs.
- The public repository, if any.
- A short description within registry limits.

## Copy rules

- No em dashes, no emojis, no hype words; editors reject AI-sounding copy.
- No claim that is not in the products note.
- Counts written as floors that stay true.
