# Building the fence table

Read the pricing note and fill one row per need. Every cell comes from the note; leave a cell empty rather than guess.

```text
| Need | Smallest option that covers it | Fence that decides (limit or feature) | Monthly price | Yearly price (if published) |
| Trying it out | <free tier> | <its usage cap> | | |
| One surface or one feature only | <standalone product or add-on> | <what it includes> | | |
| Solo, light use | <entry plan> | <usage per month> | | |
| Builder with schedules | <mid plan> | <shortest schedule interval, projects> | | |
| Small team with approvals | <team plan> | <seats, approval features> | | |
| Many seats, private needs | <enterprise or contact sales> | <seats, deployment> | contact sales | |
```

## Rules

- Pick the smallest option that covers all seven qualifying facts.
- Plans that already include a standalone product cannot buy it again: check the note.
- If the public page and an internal catalog differ, quote the public page and flag the difference to the CFO.
- Never quote a value that appears only in an internal catalog.
- Contractual or per-engagement items (SSO, SLA, private deployment, dedicated support) are said as "contractual" or "per engagement", never as built features, unless the note says they are built.
- Inference or third-party usage billed by the customer's own provider is stated as such.
- Bundle totals not printed on the price list are left to the checkout configurator.
