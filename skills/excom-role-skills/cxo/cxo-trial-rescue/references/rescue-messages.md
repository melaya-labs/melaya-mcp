# Rescue causes and message patterns

## Causes

| Likely cause | Signal | Rescue angle |
|---|---|---|
| Model cannot call tools | Runs on a free or small model, agents could not act | Switch to a tool-capable model or their own key |
| No engine connected | Verified, no key, no runner | Connect one model in a minute |
| Local runner never online | Runner token created, never seen | Packaged desktop install, or a cloud model |
| Device not paired | Device product chosen, no device | Pair on the device itself |
| Approval waiting | Run paused on approval | Where to approve |
| Free limit used | Usage cap reached | Hand to the CRO, no rescue message |
| Busy, nothing failed | One short session, no errors | A template for their stated goal |
| Wrong contact | Shared or role mailbox | Ask who uses the account |

## Patterns

**Message 1, value first.** One line on what happened in their account, the fix in one or two lines, a doc link, an easy reply ("Reply yes and I'll send the steps").

**Message 2, new angle.** One sentence: "One more point: ..." or a template matched to their goal. Never "just checking in".

**Message 3, honest close.** "I'll stop here so I don't add noise. If you want the steps later, reply to this thread." Then stop.

## Rules

- Subject names their situation ("your agents could not act"), never "following up".
- Each message shorter than the last; under 90 words.
- Only to people who signed up; never to people found elsewhere.
- Recheck progress before each send.
- After the close, contact again only on a genuine new trigger (a fix shipped for their blocker, a new feature they asked for).
