# Gap scoring and customer-version template

## Scoring, 1 to 5 each (total out of 25)

| Criterion | 5 means |
|---|---|
| Impact | Blocks first success or payment |
| Urgency | Users hit it this week |
| Reach | Affects several products, plans or audiences |
| Risk | Touches security, billing or data |
| Reuse | Answers several different questions |

Rank by total; break ties by count of users who asked.

## Customer-version template

```text
Symptom: <what the user sees, with the exact message or screen>
Cause: <one line>
Fix: <numbered steps, screen names exactly as in the app>
Workaround: <if no fix yet>
Fixed on: <date, if fixed>
Related: <links to related public notes>
```

## Rules

- Write what the user sees, not internal component names.
- No internal ids, hostnames or roadmap dates.
- Keep the note a document, not a to-do list; bump its updated date.
- Translate per the team's language process once the source version is approved.
- A gap reported three times in a week also goes to the CPO as a product signal.

## Status flow

Backlog, drafting, in review, published, refresh queued.
