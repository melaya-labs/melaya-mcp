# Feedback taxonomy

Keep it lean: under 30 drivers in total.

## Layers

| Layer | Values |
|---|---|
| Persona | Builder, operator, integrator or agency, enterprise team, developer (adapt to the audiences note) |
| Lifecycle | Signup, setup, first success, daily use, upgrade, renewal or churn |
| Product | One product from the products note, or platform (account, billing, models, local runner) |
| Driver | Setup friction, model or key, local runner, device pairing, approvals, reliability, missing capability, docs gap, price or plan shape, trust and safety, performance |
| Sentiment and urgency | Negative, neutral, positive; blocking or not; one user or many |

## Confidence

| Label | Rule |
|---|---|
| High | More than five users and a behaviour signal that agrees |
| Medium | Three to five users, or many users without behaviour data |
| Low | One or two users |

## Evidence card

```text
Theme: <driver, product, lifecycle>
Count: <N users in M days, sources>
Quotes: "<...>" (<channel, date>), paraphrase labelled as such
Behaviour: <funnel or run fact>
Plans affected: <list>
Recommendation: <fix type, metric, owner>
```

## Governance

- Version every taxonomy change with a date so months compare.
- Review the driver list quarterly; merge drivers used fewer than twice a quarter.
- Positive feedback is tagged too; it feeds references and case studies.
